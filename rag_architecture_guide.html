Classic RAG

Standard dense vector retrieval pipeline. Text is chunked, embedded into vector representations, and stored in a Vector DB. User query retrieves top-K nearest neighbors based on cosine similarity and sends them to the LLM context window.

🎯 Best For: General Q&A over private document databases.

⚡ Key Strengths

  • ✓ Simple setup & low architecture footprint
  • ✓ Fast implementations using standard embedding models
  • ✓ Cost-effective baseline for unstructured text

Universal Architecture Building Blocks

4 Common Components of RAG Systems

Regardless of the specific architecture, modern RAG systems rely on these core functional units.

🔍

1. Query Processor

Normalizes user input, generates vector embeddings, or rewrites conversational queries (query expansion, sub-query decomposition, or hypothetical document embeddings HyDE).

📥

2. Retriever Engine

Interfaces with indexes (Vector Databases, Knowledge Graphs, BM25 Index). Executes top-K vector lookup, graph traversal, hybrid keyword fusion, and optional cross-encoder reranking.

⚙️

3. Context Assembler

Formats retrieved chunks, parent documents, or graph node triples into a clean prompt context block, optimizing token budgets and reducing lost-in-the-middle context degradation.

🤖

4. LLM / Generator

Receives the assembled prompt (System Instructions + Context + User Query) and synthesizes the final accurate, grounded answer with citations.

💡 Key Strategic Takeaway

Successful systems rely on selecting the right indexing format and retrieval logic based directly on the complexity of your data, enterprise security boundaries, context limits, and accuracy requirements.
